# Project Structure

**Wirya-Website** — a bilingual (Arabic/English) Next.js 16 site for Werya, a digital
transformation company. Monorepo-free single app with App Router.

```

│   │   ├── page.tsx            # Homepage

│   │   ├── services/[id]/      # Services + per-service pages
│   │   ├── blog/  blog/[id]/   # Blog list + individual posts
│   │   ├── case-studies/[id]/
│   │   ├── contact/  faq/
```

## Content architecture (important)

Admin edits are **not** stored in a database. The admin panel generates data and
pushes it back into this repository via `lib/sync-service.ts` → `app/api/sync`,
rewriting the starred `lib/*.ts` files and `content/posts/*.md`. Those files are the
**single source of truth**; the public site reads them directly at build time.

- Editing content in the admin panel commits changes to the `main` branch.
- `lib/blog.ts` is intentionally minimal (categories + types only) — it is
  regenerated by the admin and carries no duplicate post definitions.
- `lib/blog-loader.ts` owns the canonical `BlogPost` type (with `series`, `status`,
  `tags`) and all post-loading helpers.

## Commands

| Script | Purpose |
|--------|---------|
| `pnpm dev` | Start dev server on :3000 |
| `pnpm build` | Production build |
| `pnpm start` | Serve production build |
| `pnpm lint` | ESLint / Next lint |
| `pnpm type-check` | TypeScript check (`tsc --noEmit`) |
| `pnpm generate-password` | Hash an admin password (`node scripts/generate-password-hash.js <pass>`) |

## CI

`.github/workflows/ci.yml` runs type-check + lint on every push/PR to `main`.
